## 账号与计划选择（2026-11）

**入口：** [chatgpt.com](https://chatgpt.com)

| 计划 | 价格（2026-11） | 核心权益 |
|------|----------------|---------|
| **Free** | $0 | 无限文本对话（GPT-6 默认）、有限上传/图像/语音/深度研究 |
| **Go** | $8/月 | 更多上传、图像、语音、更长记忆；可能含广告 |
| **Plus** | $20/月 | 高级推理、Projects、定时任务、自定义 GPT、扩展 Codex、Agent mode、深度研究 |
| **Pro** | $100/月（5× Plus）或 $200/月（20×） | GPT-6 Astra 推理、更长 Codex / Work 会话、**Dot 常驻 Agent**、最大深度研究 |
| **Business** | $20/座/月（年付；月付 $25，至少 2 座） | 团队空间、SSO、管理控制、默认不用于训练 |
| **Enterprise** | 定制 | SCIM、数据驻留、扩展上下文、分析、合规 |

> 💡 **技术团队建议 Plus 起步**：Codex、Projects、Agent mode 是核心生产力；重 Agent 用量再评估 Pro。
>
> 价格与计划变动频繁，来源：[chatgpt.com/pricing](https://chatgpt.com/pricing)（2026-11 核对）；**以官网为准**。

## 必配：Custom Instructions（自定义指令）

**位置：** 右上角头像 → 自定义 ChatGPT

这是让 ChatGPT 永远记住你的偏好的核心设置，分两部分：

### 第一部分：关于你的背景
```
我是一个后端开发工程师，主要使用 Python 和 Go。
我们公司使用 AWS 作为云服务，PostgreSQL 作为主数据库。
我的英语不是母语，请用中文回答。
我有 5 年开发经验，不需要解释基础概念。
```

### 第二部分：你希望 ChatGPT 如何回应
```
- 代码示例优先，减少文字解释
- 直接给出最佳实践，不需要列出多个选项
- 代码要包含错误处理和类型注解
- 遇到不确定的事情，明确说明而不是猜测
- 回答要简洁，不要废话
- 复杂问题先给结论，再解释原因
```

## 模型选择（2026-11）

ChatGPT 的模型选择在不同入口里不一样，**以对话框左下角/设置里的列表为准**。

| 模型 | 定位 | 适合 |
|------|------|------|
| **GPT-6 Astra** | 最强旗舰，复杂推理 + 长任务 | 架构设计、疑难 Bug、复杂 Agent 任务 |
| **GPT-6.1 Sol** | 接近 Astra、成本更低 | 日常复杂任务、代码 |
| **GPT-6.1 Terra** | 快速、视觉/电脑操作、写作 | 多模态、界面操作、文档 |
| **GPT-6 Luna** | 最省钱、高并发 | 简单问答、摘要、批量任务 |

> GPT-6 Astra 于 2026-09-03 发布（09-04 起公开）；GPT-6.1 Sol 于 2026-09-29 发布。**具体哪个计划默认哪个模型，OpenAI 调整很频繁**，以客户端为准。

**选择原则：**
- 80% 的任务用默认模型（Luna / Sol）就够
- 遇到复杂推理、长任务，手动切 Astra
- 需要看图/操作界面，用 Terra

## 内置工具的正确打开方式

### 联网搜索
```
何时用：
✅ 查最新文档、版本信息
✅ 搜索刚发布的工具或库
✅ 验证时效性信息

何时不用：
❌ 通用编程问题（训练数据已有，搜索反而慢）
❌ 代码调试（不需要实时信息）
```

### 代码解释器（Code Interpreter）
```
最强大的内置工具之一，能执行 Python 代码。

使用场景：
1. 数据分析
   上传 Excel/CSV → "分析销售趋势，画折线图，找出异常"

2. 文件处理
   上传 PDF → "提取所有表格数据，转成 Excel"
   上传图片 → "识别图中的文字内容"

3. 数学计算
   "解这道微分方程，给出解析解和数值解，画出图像"

4. 代码运行验证
   "运行这段 Python，告诉我输出结果"
   "这个正则表达式匹配 '2026-03-14' 吗？测试一下"
```

### 图像生成（GPT Image）
```
触发方式：直接描述你想要的图

有效 Prompt 结构：
"[风格] + [内容描述] + [细节] + [构图]"

例：
"扁平插画风格，一个开发者坐在电脑前，
屏幕显示代码，背景有 AI 机器人在协作，
暖色调，简洁现代"
```

### Deep Research / Agent mode
- **Deep Research**：多步检索 + 长报告，适合调研、竞品分析、技术选型
- **Agent mode**：让 ChatGPT 自己操作浏览器/工具完成任务，适合“帮我填表、查资料、整理成文档”
- 两者都消耗较多额度，先从小任务试

## Projects（项目上下文）

**位置：** 左边栏 → 项目 → 新建项目

Projects 让 ChatGPT 记住特定项目的上下文：

```
创建项目：后端开发项目

添加项目指令：
"这个项目是我们的电商后端，使用 FastAPI + PostgreSQL。
以下是项目的数据库 Schema：[粘贴 Schema]
以下是 API 规范文档：[粘贴文档]
本项目所有对话都要基于这个上下文。"

上传文件：
- 项目 README.md
- 数据库设计文档
- API 接口文档
```

之后在这个项目里的所有对话，ChatGPT 都会记住这些背景。

> 2026 年 Projects 还支持**定时任务 / 计划任务**：可以让它按周生成报告、巡检等。

## Dots：常驻 Agent（2026 新形态）

**位置：** ChatGPT 客户端 / 网页（Pro 与 Business Premium 首批）

Dots 是 OpenAI 在 2026-09-29 DevDay 发布的**常驻 Agent**：

- 由 GPT-6 Astra 驱动，有自己的**云电脑和浏览器**
- 可以连接你的应用（官方称 4000+ 应用/插件），在后台持续推进任务
- 有独立记忆，能学习你的偏好；敏感操作需要你批准
- 首个 Dot 包含在 Pro / Business Premium 计划内，对话不计入普通用量

**适合：**
- 长期跟踪型任务（等 CI、盯反馈、整理周报）
- 需要跨应用执行的重复流程

**注意：**
- 它会「主动做事」，权限要一开始就收紧
- 重要操作仍要人工复核（官方也提示会犯错）

来源：[OpenAI Dots 功能页](https://chatgpt.com/features/dots/)、DevDay 2026 报道（2026-09-29）。

## 插件（Plugins）

**位置：** 侧边栏 → 插件 / `chatgpt.com/plugins`

2026 年 ChatGPT 用 **Plugins** 接外部工具：Slack、SharePoint、Airtable、Google Drive、Jira、Figma 等。

- 用 `@插件名` 在对话里调用，例如 `@Airtable, 把会议下一步拉出来`
- 管理员可以控制哪些插件可用、能做什么动作
- 企业版需要管理员先在 Workspace 设置里启用

> 对开发团队最常用的是 GitHub、Jira、Slack、Figma 这几类。

## GPT 功能（自定义 AI 助手）

**位置：** 左边栏 → 探索 GPT / GPT 商店

你可以创建专属 GPT，也可以使用别人分享的：

### 创建团队专属 GPT

**位置：** 右上角 → 我的 GPT → 创建

```
名称：[公司名] 技术助手

指令（System Prompt）：
你是 XX 公司的内部技术助手。
你熟悉我们的技术栈：Python/FastAPI/PostgreSQL/AWS。
你了解我们的代码规范（参见上传的文档）。
回答时优先考虑我们的实际使用场景。
遇到不确定的内容，明确说明并建议查阅内部文档。

上传知识库：
- 公司编码规范.pdf
- API 设计指南.md
- 常见问题 FAQ.md
```

创建好后可以分享给团队成员使用。

## Codex：在 ChatGPT 里写代码（2026）

ChatGPT 计划自带 **Codex** 额度：

- 入口：ChatGPT 侧边栏 → Codex，或桌面 App（macOS / Windows）
- 适合：让 Codex 在云端跑任务、开 PR、做代码审查
- 模型：GPT-6.1 Sol / GPT-6 Astra / GPT-6 Luna 等（按计划限额）
- 详见 [M3-03 其他主流工具](../03-ai-coding-tools/03-other-tools.md)

> 对开发同学：**ChatGPT 不只是聊天窗口，Codex 才是它真正的编程入口。**

## 记忆功能

**位置：** 设置 → 个性化 → 记忆

开启后 ChatGPT 会自动记住你说过的重要信息。

你也可以主动告诉它：
```
"记住：我们公司所有项目都用 poetry 管理依赖"
"记住：我更喜欢 PostgreSQL 而不是 MySQL"
"记住：代码示例用中文注释"
```

查看记忆内容：设置 → 个性化 → 管理记忆

## 高效对话技巧

### 分步拆解复杂任务
```
❌ "帮我设计一个完整的微服务架构"

✅ 步骤一："列出设计微服务系统需要考虑的维度"
✅ 步骤二："针对服务拆分这个维度，给出具体方案"
✅ 步骤三："这个方案的服务间通信该如何设计？"
```

### 要求输出格式
```
"用表格对比 Redis、Memcached、本地缓存三种方案"

"用 Mermaid 语法画出这个系统的流程图"

"给我一个 JSON 格式的配置模板"
```

### 连续迭代
```
→ "写一个用户注册接口"
→ "加上邮件验证功能"
→ "把错误信息改成中文"
→ "添加请求频率限制，同一 IP 1分钟内只能注册3次"
```
