# M1-03 · 训练过程：预训练、微调与 RLHF

> 📅 内容基准：2026-11 ｜ ⏱️ 时效性：低 ｜ 🔁 下次复核：2027-05
>
> LLM 是怎么从零"学会"说话的？经典三阶段 + 2026 年的新后训练菜单。

---

## 训练三部曲（经典框架仍然成立）

```
阶段一：预训练（Pre-training）      → 学会语言与知识
    ↓
阶段二：监督微调（SFT）             → 学会"听指令"
    ↓
阶段三：偏好对齐（RLHF / DPO）      → 学会"说人话、说好话"
    ↓
（2025-2026 新增）强化学习 / RLVR   → 学会"推理与用工具"
```

这个框架是理解训练的骨架。2026 年的新模型并不是推翻它，而是在第三阶段之后又加了一层："怎么把难题做对"。

---

## 阶段一：预训练

### 数据
- 来源：Common Crawl（网页）、书籍、GitHub 代码、Wikipedia、学术论文，2026 年还包括大量图像/音频/视频对齐数据
- 规模：数万亿 Token 起（具体数字以各模型技术报告为准）
- 质量：要大量清洗过滤、去重、去毒，数据配比本身是核心竞争力

### 目标
**自监督学习**：给模型看一句话的前半部分，让它预测下一个词。不需要人工标注。

```
输入：["今天", "的", "天气", "是"]
目标：["的",   "天气", "是",  "晴天"]（向后移一位）
```

### 成本
- 需要数千张 GPU/NPU，跑数周到数月
- 成本取决于模型规模、数据量、芯片和工程效率；2026 年旗舰模型的训练成本基本不再公开
- 一个反直觉事实：**训练是一次性成本，推理是长期成本**。很多团队的账单主要花在推理上

### 结果
得到一个 **Base Model（基座模型）**，能续写文本，但不会"对话"，更不会"听指令"。

---

## 阶段二：监督微调（SFT）

### 问题
Base Model 只会续写文本，你问它"怎么写 Python"，它可能给你续写一道数学题。

### 解决
人工标注（2026 年也大量用强模型合成 + 人工校验）"指令-回答"对：

```json
{
  "instruction": "用 Python 写一个冒泡排序",
  "response": "def bubble_sort(arr):\n    ..."
}
```

用这些数据微调模型，让它学会"按指令回答"。

### 特点
- 数据量小得多（几千到几十万条）
- 但质量要求高，不好的数据会损害模型
- 效果显著：模型从"续写机器"变成"指令跟随者"

---

## 阶段三：偏好对齐（RLHF / DPO）

### 问题
SFT 之后模型能回答问题，但回答质量参差不齐，甚至可能有害。

### 核心思想

让人类（或强模型）评估模型的回答，训练一个**奖励模型（Reward Model）**，再用强化学习优化 LLM。

### 流程

```
1. 让模型对同一问题生成多个答案
        ↓
2. 人工/模型排序：答案 A > 答案 C > 答案 B
        ↓
3. 用排序数据训练奖励模型（打分器）
        ↓
4. 用 PPO 等强化学习算法，让 LLM 最大化奖励分数
        ↓
5. LLM 学会产出"人类认为更好"的回答
```

### 效果
- 更有帮助（helpful）
- 更诚实（honest）
- 更无害（harmless）
- Anthropic 称之为 **HHH 原则**

### 简化方案
RLHF 训练复杂、不稳定。后来出现了更省事的替代：

| 方法 | 特点 |
|------|------|
| **DPO**（Direct Preference Optimization） | 不需要单独训练奖励模型，直接用偏好对训练 |
| **GRPO**（Group Relative Policy Optimization） | DeepSeek-R1 使用，用组内相对分数替代 Critic，训练推理能力更省资源 |

## 2025-2026 新增：RLVR 与"推理后训练"

推理模型（o1 / R1 之后）的关键，不只是"想得更久"，而是**用可验证的奖励来训练"想对"**。

**RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习）**：

```
模型生成多条解题过程
    ↓
用"可自动验证"的信号打分：
  数学题 → 答案对不对
  代码题 → 测试过不过
  工具任务 → 最终状态对不对
    ↓
强化学习：提高"能通过验证"的思考路径的概率
```

这解释了 2025-2026 的一个趋势：**后训练的重点从"让人喜欢"转向"让结果正确"**。数学、代码、Agent 任务因此提升最快。

> 不是所有任务都有"标准答案"。写作、咨询、设计类任务仍依赖偏好对齐与人类评审。

---

## 推理模型（Reasoning / Thinking）到底怎么工作？

2024 年后的新范式：让模型在回答前先做"内部推理"（Chain of Thought），再给出答案。

```
用户: 9.9 和 9.11 哪个大？
模型内部思考:（比较小数位：9.9 = 9.90，9.11 = 9.11，9.90 > 9.11）
模型输出: 9.9 更大
```

### 2026 年的产品形态

| 形态 | 说明 | 代表 |
|------|------|------|
| **双模式** | 同一模型可切"思考 / 不思考" | DeepSeek V4 的 Thinking / Non-Thinking 模式（[官方文档](https://api-docs.deepseek.com/guides/thinking_mode)，2026-11） |
| **自适应思考** | 模型自己决定何时想、想多久 | Claude Opus 5.5 的 adaptive thinking 默认常开（[Effort 文档](https://platform.claude.com/docs/en/build-with-claude/effort)，2026-11） |
| **思考强度档位** | 用 `effort` 在 low / medium / high / xhigh / max 之间调 | GPT-6 Sol、Claude 5.5 系列均提供 effort 控制 |
| **思考 Token 计费** | 思考过程算输出 Token，影响成本与延迟 | 主流 API 均已如此 |

> 结论：2026 年"要不要思考"不应由用户猜，而应由**任务难度 + 成本预算 + 评测结果**决定。简单任务开 max 是浪费，难题开 low 是自欺欺人。

## 关键结论

1. **预训练给知识**，微调给"行为"，偏好对齐给"分寸"，RLVR 给"做对难题的能力"
2. RLHF / DPO 让模型"懂人话、说人话"
3. 训练一次成本极高，推理（用）成本才是长期账本
4. 推理模型通过"慢思考 + 可验证奖励"解决复杂问题
5. MoE、长上下文、多模态让训练与推理的工程复杂度都上了一个台阶

## 历史沿革

- **2026**：Thinking 模式成为默认能力，effort 成为标准参数；RLVR 成为推理/代码/Agent 后训练主线；1M 上下文与 MoE 训练工程化。
- **2025**：DeepSeek-R1 公开 GRPO 路线；"推理模型"从闭源走向开源；后训练开始大规模使用可验证奖励。
- **2024**：OpenAI o1 展示 test-time compute scaling；DPO 成为 RLHF 的常见替代。
- **2022-2023**：RLHF 成为 ChatGPT / GPT-4 的关键配方；Llama 系列推动开源微调生态。
- **2020**：GPT-3 + Scaling Laws 确立"预训练大模型"范式。
