# M1-01 · 什么是大语言模型（LLM）

> 📅 内容基准：2026-11 ｜ ⏱️ 时效性：低 ｜ 🔁 下次复核：2027-05
>
> 5 分钟读懂 LLM 是什么、能做什么、不能做什么；顺带建立 2026 年的新认知。

---

## 一句话定义

**大语言模型（Large Language Model，LLM）** 是一种在海量文本（2026 年的旗舰模型还包括图像、音频、视频等）上训练出来的 AI 模型，能够理解和生成自然语言。

到 2026 年，更实用的定义是：

> **LLM = 一个会预测下一个 Token 的模型 + 一整套让它"会思考、能动手"的工程外壳（harness）。**

同一个模型，放进聊天框是助手，接上工具和循环就是 Agent。理解这一点，比记住某个版本号更重要。

---

## 它是怎么来的？

想象你读了互联网上几乎所有的文章、书籍、代码、论坛帖子——规模是 **数万亿个 Token**。读完之后，你的大脑形成了对语言模式的深刻理解：什么词后面跟什么词，什么问题通常有什么答案，代码应该怎么写。

LLM 做的就是这件事，但规模大得多。2026 年许多旗舰模型采用 **MoE（混合专家）** 架构，总参数动辄数千亿到上万亿，但每次推理只激活其中一小部分（见 [M1-02](./02-transformer.md)）。

---

## 它的本质：预测下一个 Token

LLM 的核心任务其实很简单：

```
给定一段文字，预测下一个词（Token）是什么
```

例如：
- 输入："今天天气很"
- 预测：好 / 热 / 冷 / 差 / 晴...（每个词都有概率）

通过一遍遍预测，就能生成连贯的文章、代码、对话。

**2026 年的补充**：推理模型（Reasoning Model）会在给出最终答案前，先生成一段"思考 Token"（thinking）。本质上仍是逐 Token 预测，只是把"想"也变成了可计算、可计费的输出。

## 能做什么

| 能力 | 例子 |
|------|------|
| 📝 文本生成 | 写文章、邮件、报告 |
| 💬 对话理解 | 客服、问答、聊天 |
| 🧠 推理分析 | 数学题、逻辑推断、方案权衡 |
| 💻 代码编写 | 生成、解释、Debug、跑测试、改仓库 |
| 🌐 翻译 | 多语言互译 |
| 📊 摘要提炼 | 长文总结、要点提取、跨文档对比 |
| 🔧 格式转换 | JSON/Markdown/表格互转；结构化输出 |
| 🖼️ 多模态理解 | 读截图、看图表、听音频、看视频（原生多模态模型） |
| 🛠️ 调用工具 | 搜索、读文件、查数据库、操作浏览器（Agent 化） |

## 不能做什么（常见误区，2026 版）

| 误区 | 真相 |
|------|------|
| ❌ LLM 知道"最新"信息 | 训练有知识截止日期；但 2026 的模型可通过搜索 / 工具 / 文件实时取数——关键看有没有接工具 |
| ❌ LLM 永远正确 | 会"幻觉"；推理模型也会，而且更擅长"自圆其说"，引用也可能是编的 |
| ❌ LLM 能记住你 | 模型本身无状态；产品层用 memory / projects / 会话历史模拟记忆，换会话不一定还在 |
| ❌ LLM 在"思考" | 推理模型确实会花算力生成思考 Token；但这仍是模式计算，不等于人类意义上的理解 |
| ❌ LLM 理解世界 | 多模态模型能"感知"图像和声音，但感知不等于理解因果 |
| ❌ 参数越大越好 | 2026 年要比"总参数 + 激活参数 + 数据 + 推理预算"，小模型在窄任务上经常更划算 |
| ❌ 上下文窗口越大越省心 | 窗口变大不等于注意力不衰减；"上下文腐烂（context rot）"依然存在，塞得越多不一定越好 |

---

## 参数量代表什么？

常听到"70B 模型"、"千亿参数"，参数就是模型中可学习的权重数量。2026 年要区分两个数：

| 概念 | 含义 | 例子（2026-04，DeepSeek 官方） |
|------|------|------|
| **总参数（Total）** | 模型里一共有多少权重 | DeepSeek-V4-Pro：1.6T 总参数 |
| **激活参数（Active）** | 每次推理真正参与计算的权重 | DeepSeek-V4-Pro：49B 激活；V4-Flash：284B 总 / 13B 激活 |

这解释了为什么"1.6T 的模型能跑得动"：MoE 每次只叫醒一部分专家。

- 参数越多 → 通常能记住更多知识、处理更复杂的问题
- 激活参数越多 → 单次推理越贵、越慢
- **不是越大越好**：小模型 + 好工具 + 好上下文，常常打赢大模型裸跑

常见量级（粗略直觉，具体以各模型官网为准）：
- **8B–30B**：可以本地跑，适合轻量任务、私有化
- **100B–300B（MoE 为主）**：质量与成本平衡，常见于"Flash / 轻量旗舰"
- **1T+（MoE）**：前沿旗舰，需要专业集群或 API

## 2026 年的五个新变化

| 变化 | 你可以怎么用 |
|------|--------------|
| **推理模型 / Thinking** | 难题开思考模式，简单任务关掉或降 effort，省钱省时 |
| **MoE 稀疏激活** | 不再用"参数量"单一维度判断强弱 |
| **1M 级长上下文** | 整本手册、整个中型仓库、多份合同可以一次读入 |
| **上下文缓存** | 长系统提示、固定文档、代码库前缀可缓存，成本大幅下降 |
| **Agent 化** | 把 LLM 接上工具 / MCP / Skills，让它自己查、自己改、自己验证 |

## 关键词速查（先混个脸熟）

| 术语 | 解释 |
|------|------|
| **Token** | 模型处理的最小单位，约等于 0.75 个英文单词或半个中文字 |
| **Context Window** | 模型一次能"看到"的最大 Token 数；2026 旗舰普遍到 1M 级 |
| **Context Caching** | 缓存重复的上下文前缀，命中后按更低价计费 |
| **Temperature** | 控制输出随机性；推理模型通常忽略该参数，改用 effort 控制思考深度 |
| **Reasoning Effort** | 思考强度档位（如 low / medium / high / xhigh / max），影响质量、延迟与成本 |
| **Hallucination（幻觉）** | 模型自信地输出错误信息，包括编造引用 |
| **Tool Call** | 模型输出结构化的工具调用指令，由程序执行后把结果回传 |
| **MCP** | Model Context Protocol，AI 接外部工具/数据的开放标准 |
| **MoE** | 混合专家，总参数大、单次只激活部分专家 |

更完整的表见 [M1-04 核心概念速查](./04-key-concepts.md)。

## 历史沿革

- **2026**：1M 上下文成为旗舰标配；Thinking 模式普及并可用 effort 调节；原生多模态、上下文缓存、Agent 化使用成为默认工作方式。
- **2025**：DeepSeek-R1 把"推理模型 + 开源"推向大众；MCP 成为工具接入事实标准；Agent 编程工具爆发。
- **2024**：OpenAI o1 开启"先思考再回答"范式；GPT-4o 推动多模态交互。
- **2022-2023**：ChatGPT 让 LLM 出圈；GPT-3.5 / GPT-4 确立"预训练 + 对齐"的产品形态。
- **2020**：GPT-3（175B）证明"规模就是能力"，Scaling Laws 成为主线。
- **2017**：Transformer 论文发表，奠定此后所有主流 LLM 的结构基础。
