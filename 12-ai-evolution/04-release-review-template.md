# M12-04 · 新版本评估模板

> 每次有新模型、新工具、新 Agent 工作流出现时，团队不要只转发链接。用这份模板快速判断：它是什么、解决什么、值不值得试、怎么试。
>
> 最后更新：2026年6月

---

## 1. 基本信息

```text
名称：
厂商/作者：
发布时间：
类型：模型 / 工具 / Agent 工作流 / 协议 / 开源项目
官方链接：
一句话总结：
```

---

## 2. 它属于哪个发展阶段？

选择一个：

- [ ] 聊天机器人
- [ ] 工具调用
- [ ] 编程助手
- [ ] Agent 执行循环
- [ ] 自审查 / 自迭代
- [ ] Cloud Agent
- [ ] 团队级 Agent 工作流

说明：

```text
它相比上一代主要多了什么能力？
```

---

## 3. 解决了什么问题？

```text
旧问题：

新能力：

对我们团队的意义：
```

示例：

```text
旧问题：AI 写完代码后不自查。
新能力：加入 Reviewer 和测试循环。
意义：可以把 PR 初筛交给 Agent，但最终仍由人合并。
```

---

## 4. 对团队的影响

| 维度 | 判断 |
|------|------|
| 开发效率 | 提升 / 不确定 / 无影响 |
| 成本 | 降低 / 升高 / 不确定 |
| 安全 | 更安全 / 风险增加 / 无变化 |
| 学习成本 | 低 / 中 / 高 |
| 是否影响现有流程 | 是 / 否 |

---

## 5. 小规模试点方案

```text
试点场景：
参与人员：
试点任务：
成功标准：
失败标准：
试点周期：
```

成功标准不要写“感觉更好”，要写可验证标准：

- PR 返工次数降低
- 测试覆盖增加
- Bug 修复时间减少
- 文档维护成本降低
- 人工 Review 发现的问题减少

## 和自动维护机制的关系

当前仓库已经有每 3 天自动更新时间戳和巡检报告的机制。  
但“新版本是否值得采用”不能完全自动判断，需要用本模板做人工/Agent 协同评估。

建议流程：

```text
自动发现/团队转发新版本
  ↓
用本模板做初评
  ↓
小任务试点
  ↓
写入 M2/M3/M5/M10/M11 或本模块
```
