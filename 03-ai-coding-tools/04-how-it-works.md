# M3-04 · AI 编程工具底层原理

> 📅 内容基准：2026-11 ｜ ⏱️ 时效性：高 ｜ 🔁 下次复核：2027-02
>
> 原理部分长期有效；「2026 的 Agentic 架构」是当前快照，会随产品演进而变化。

---

## 一句话结论

AI 编程工具的本质没变：**决定把什么上下文喂给模型，把模型的输出变成可执行的修改，再通过工具调用形成循环**。2026 年新增的是「循环的规模化」——子 Agent、并行执行、上下文压缩、权限与沙箱，让 Agent 能连续跑几小时而不是几分钟。

---

## 整体架构（2026 版）

```
你写的代码 + 指令（终端 / IDE / Web / Slack）
    ↓
[上下文构建] ← 系统提示、规则、记忆、检索、工具定义
    ↓
[LLM 请求]（Claude 5.5 / GPT-6 / Gemini 4 / Grok 4.7 …）
    ↓
[Agent 循环]
    ├── 模型决定调用哪个工具（读文件 / 改文件 / 跑命令 / 搜索 / 浏览器 / MCP）
    ├── 工具执行（可能在沙箱里、可能需要审批）
    ├── 结果回填上下文
    └── 继续，直到完成 或 触发上下文压缩 / 人工介入
    ↓
[Diff 应用 + 审查 + 提交]
    ↓
你的代码被修改 / 你得到回答 / 云端 Agent 产出 PR
```

## 关键技术一：上下文构建

AI 编程工具最重要的工作，就是**决定把什么内容发给 LLM**。

上下文包含：

```
1. 系统提示词（System Prompt）
   - 角色、工具定义、输出规范
   - 当前语言/框架信息

2. 项目规则与记忆
   - AGENTS.md / CLAUDE.md / .cursor/rules
   - 自动记忆（auto memory）

3. 当前文件内容

4. 相关文件（检索）
   - 语义检索（RAG）+ 关键词/结构搜索
   - @引用 手动指定

5. 工具结果（命令输出、测试结果、网页内容）

6. 对话历史（可能已被压缩成摘要）
```

**为什么这很重要？**

LLM 不知道你的项目长什么样。工具的核心价值，就是把最相关的代码「喂」给模型，让它能给出准确答案。**上下文越干净、越相关，Agent 越不容易跑偏，也越省钱。**

---

## 关键技术二：代码库索引（Embedding）

当你打开项目时，工具会在后台：

```
1. 读取项目文件（排除 .gitignore）
       ↓
2. 把文件/函数切成小块（Chunk）
       ↓
3. 转成 Embedding（向量）
       ↓
4. 存到本地或云端索引
```

问问题时：

```
问题 → Embedding → 向量检索最相关的代码块
     → 相关代码块 + 问题 + 规则 一起发给 LLM
```

这就是工具能「理解整个项目」的原因：**语义搜索 + 结构化检索**。2026 年的工具通常还会混合 grep / AST / 符号索引，不只依赖向量。

**这个技术叫做 RAG（Retrieval-Augmented Generation）**，详见 [M4-02 RAG](../04-principles/02-rag.md)。

---

## 关键技术三：代码补全（FIM）

Tab 补全用的是特殊技术 **FIM（Fill-In-the-Middle）**：

```
[PREFIX] 光标前的代码
[SUFFIX] 光标后的代码
[MIDDLE] ← 模型预测这里应该填什么
```

**为什么补全这么快？**
- 专用小模型（不是旗舰大模型）
- 量化压缩，本地或边缘节点运行
- 预填充 + 缓存减少延迟

> 2026 年补全仍然由小模型承担；Agent 能力则交给旗舰模型，两者不是同一个成本模型。

## 关键技术四：Agent 循环

Agent 能「自动完成任务」，背后是 **Agent 循环**：

```python
while True:
    response = llm.call(messages, tools=TOOLS)

    if response.stop_reason != "tool_use":
        break  # 任务完成

    for tool_call in response.tool_calls:
        result = execute(tool_call)   # 可能被权限系统拦截/需审批/在沙箱执行

    messages.append(tool_results)
```

**常见工具清单：**
- `read_file` / `write_file` / `edit_file`
- `search_codebase` / `grep` / `glob`
- `run_command`（终端）
- `browser`（打开网页、截图、点击）
- `mcp__*`（通过 MCP 接入的外部工具）
- `task`（派发子 Agent）

---

## 关键技术五：Diff 应用

模型生成修改后，工具把它变成「接受/拒绝」界面：

```
原始代码：          LLM 生成：
def foo():    →    def foo():
    x = 1              x = 2      ← 修改
    return x           y = x + 1  ← 新增
                       return y    ← 修改
```

工具计算差异（Diff），高亮显示变化。2026 年的 Agent 更多是**边工作边展示 diff**，而不是最后一次性给你一大坨。

## 2026 新增：Agentic 架构的四个关键词

### 1. 子 Agent（Subagent）

主 Agent 把「研究 / 搜索 / 读大文件」这类任务派给子 Agent，子 Agent 在自己的上下文窗口里干活，只把**摘要**回传。

- 好处：大文件读取不污染主上下文，主 Agent 保持「干净」
- 代价：多一次模型调用，延迟和成本上升
- 典型：Claude Code 的 subagents、Codex 的 subagents、Antigravity 的动态子 Agent

### 2. 并行（Parallelism）

多个 Agent 同时跑不同子任务：

- 不同文件 / 不同模块的并行开发
- 「竞品假设」并行调试（多个 Agent 各试一种解释）
- 云端 Agent 批量跑任务

Claude Code 的 **Agent Teams**（实验）是典型：一个 lead 协调，多个 teammate 各有上下文、共享任务列表、可直接互相消息。**注意：token 成本显著高于单会话，顺序任务不要用。**

### 3. 上下文压缩（Compaction）

上下文窗口再大也会满。2026 年的标准做法：

- **自动压缩**：接近上限时把历史总结成结构化摘要
- **手动压缩**：`/compact`、指定重点（如「保留 auth bug 的修复」）
- **Rewind / 回滚**：截断到之前某一轮，复用已有缓存
- **子 Agent 隔离**：把大读取放到子上下文
- **外部记忆**：CLAUDE.md / AGENTS.md / auto memory 在压缩后重新注入

压缩不是「无损」的：路径规则、嵌套规则可能被摘要掉，重要约束要放在根级规则文件里。

### 4. 工具权限（Permissions & Sandbox）

Agent 能跑命令，就必须有边界：

- **审批模式**：每个危险命令人工确认（rm、push、DROP）
- **沙箱**：文件系统 / 网络 / 进程隔离
- **路径范围**：只允许读写指定目录
- **权限配置文件**：项目级 allow / deny 列表
- **审计日志**：记录 Agent 执行了什么

> 2026 年的共识：**Agent 的能力上限取决于权限设计**。给得太多会误伤，给得太少会频繁卡住。

## 2026 新增：扩展机制（Skills / Plugins / MCP）

| 机制 | 作用 | 典型 |
|------|------|------|
| **MCP** | 把外部工具/数据接进来（数据库、GitHub、浏览器） | [M8 MCP 精选](../08-mcp/README.md) |
| **Skills** | 把可复用工作流打包，按需加载 | [M5-04b Skills](../05-practical/04-skills.md) |
| **Plugins** | 把 Skills + MCP + 子 Agent 打成可一键安装的包 | Claude / Cursor 插件市场 |
| **Hooks** | 在工具调用前后自动执行脚本（格式化、lint） | Claude Code hooks |

**为什么重要？** 模型能力趋同时，**「谁的扩展生态更好」** 就成了工具差异化的关键。

## 为什么有时候它会"出错"？

理解原理后，你就能理解局限：

| 问题 | 原因 |
|------|------|
| 不了解你的业务逻辑 | 它只看到代码，看不到需求背景 |
| 生成过时的库用法 | 训练数据有截止日期 |
| 跨文件任务出错 | 上下文窗口装不下所有相关代码 |
| 修改了不该改的代码 | Agent 判断失误，工具调用错误 |
| 重复生成类似内容 | 缺乏记忆 / 压缩丢了历史 |
| 并行 Agent 互相踩踏 | 共享文件/任务没有切分好 |
| 长任务越跑越贵 | 每轮都要重读上下文，缓存失效时成本陡增 |

## 本地 vs 云端的区别

| 维度 | 云端模型（Claude/GPT/Gemini） | 本地模型（Ollama） |
|------|------------------------------|-------------------|
| 质量 | 更强 | 受限于硬件 |
| 速度 | 受网络影响 | 极快（本地） |
| 隐私 | 代码发给第三方 | 完全本地 |
| 成本 | 按 Token 计费 | 一次性硬件投入 |
| 适合 | 大多数场景 | 数据安全要求高 |

> 2026 年多了第三种：**云端 Agent**（Cursor Cloud / Codex Cloud / Devin Cloud）。代码在云端沙箱里跑，你只审 PR——隐私与合规要单独评估。

## 实用结论

1. **工具质量 = 上下文质量**：给 AI 提供越精准的代码片段，答案越好
2. **大文件拆分**：文件太大超出上下文，AI 可能看不完整
3. **明确的 @引用**：手动指定比让工具自动猜更准
4. **Agent 模式要监督**：自动任务可能误改，保持 git 干净，随时可回滚
5. **规则要短而硬**：`AGENTS.md` / `.cursor/rules` 写「必须遵守」的约束，别写成长篇文档
6. **权限先收紧再放宽**：先只读、再小范围写、最后才放开命令执行
7. **并行不是免费的**：子 Agent / Agent Teams 的 token 成本更高，任务要能独立切分才值得

---

## 历史沿革

- **2026-11**：新增「子 Agent / 并行 / 上下文压缩 / 工具权限」四节，以及 Skills / Plugins / Hooks 扩展机制。
- **2026**：Agent 从「单会话循环」走向「多 Agent 编排 + 云端执行」；上下文压缩、权限沙箱成为标配。
- **2025**：MCP 成为事实标准；Agent 模式（Cursor Agent、Claude Code）普及。
- **2024 及以前**：以 RAG 代码库索引 + FIM 补全 + 聊天为主，Agent 循环刚出现。
