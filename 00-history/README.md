# M0-00 · AI 演进史（模块导读）

> 🕰️ 历史档案 ｜ 记录范围：1956 – 2026-11 ｜ 只追加，不回改
> 📅 内容基准：2026-11 ｜ 时效性：历史层（不做时效复检）

---

## 一句话结论

**看懂 AI 为什么长成今天这样，比记住今天哪个模型排第一更有用。**

M0 不是"新闻合集"，而是这门课的**时间坐标系**：后面 M1–M11 讲的每个概念、每件工具、每次选型，都能在这里找到它"什么时候出现、为什么出现、后来被什么取代"。

---

## 为什么单独记录历史

1. **技术判断有保质期，判断的依据没有。** 2023 年"上下文只有 8K，所以要 RAG"是合理的；2026 年上下文到 1M，RAG 没有消失，而是变成了"按需检索"。只记结论会误判，记下当时的约束才不会。
2. **团队需要共同的参照系。** 新同学容易把"Agent Teams""Skills""MCP"当成天生就有的东西；老同学容易把两年前的方案当默认答案。历史层让两代人都能对上时间。
3. **避免重复踩坑。** 很多"新范式"是旧问题的新解法：工具调用解决"模型不能行动"，RAG 解决"模型不知道你的数据"，Context Engineering 解决"塞太多反而变笨"。看清问题，才不会被名词带着走。
4. **课程本身也是史料。** MAINTAINING.md 要求"记录历史，而不是覆盖历史"——旧版本、旧判断降级保留，而不是删掉。M0 就是这条原则的落地。

## 历史层的"只追加，不回改"原则

这一层和 M1–M11 的维护方式不同：

| 规则 | 含义 |
|------|------|
| **只追加** | 新事件、新版本往对应年份/家族里加行；不重写旧行。 |
| **不回改** | 旧判断即使后来被证明错了，也保留原文，在下方补"后来发生了什么"。**错误判断本身是教材。** |
| **标注时间** | 每条尽量写到日；只有月份写到月；不确定写"据媒体报道"。 |
| **来源可查** | 关键里程碑给官方发布页/文档/权威第三方链接。 |
| **允许存疑** | 查不到就写"待核实"或省略，**不编造**。 |

> 例外：明显的错别字、失效链接可以修；**事实和判断不改**。修订记录写在文末"修订说明"。

## 与 M1–M11 的关系

```
M0 历史层（本模块，只追加）
 ├─ 解释"为什么会有这个知识点"
 ├─ 提供"旧版本/旧判断"的存档
 └─ 给时效层模块提供时间锚点
        │
        ├── M1 原理：Transformer、训练、对齐
        ├── M2 模型格局：各家族现状（M0 记演进，M2 记当下）
        ├── M3 编程工具：Claude Code / Codex / Cursor 的产品史
        ├── M4 底层原理：RAG、Agent、MCP 的问题背景
        ├── M5 实战：Prompt / Tools / Skills / Multi-Agent 的用法演进
        ├── M7 / M8：Skills 生态与 MCP 生态
        ├── M10：Cloud Agent / 常驻 Agent
        └── M11：提效工具的代际变化
```

**分工口诀：**

- **M0 记"怎么走到今天"**（历史、判断、版本演进）
- **M2 记"今天是什么样"**（当前快照 + 选型方法）
- **M5 记"今天怎么做"**（可执行的最佳实践）

同一个模型，M0 写它每一代的变化，M2 只写"截至 2026-11 的现状"。

## 维护约定

- **更新频率**：重大发布后 1 周内补 01；每年 1 月补 04 的年度回顾；03 随大版本更新。
- **来源优先级**：官方发布页 / changelog / 模型卡 > Wikipedia / LMArena / Artificial Analysis > 媒体报道（仅作时间线佐证）。
- **日期口径**：优先写"官方发布日"；如果"发布"和"可用"分两天（如预览→公开），两个都写。
- **本模块不接受自动改写**：自动化只负责体检链接，不负责改内容（见 [MAINTAINING.md](../MAINTAINING.md)）。
