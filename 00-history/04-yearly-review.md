# M0-04 · 年度回顾 2023–2026：当年的判断，后来的现实

> 🕰️ 历史档案 ｜ 记录范围：2023 – 2026-11 ｜ 只追加，不回改
> 📅 内容基准：2026-11 ｜ 时效性：历史层（不做时效复检）

---

## 为什么写年度回顾

技术史容易写成"英雄榜"：谁发布了什么、谁第一。但对团队更有用的是**认知轨迹**：

> 当年我们为什么会那样判断？哪些判断对了，哪些错了？错在哪里？

这一篇不追求精确到天，也不追求"事后诸葛亮"。它记录的是一群使用者在当时信息条件下的真实判断——**包括错的**。因为下一次范式转移来临时，我们还会经历同样的信息不足。

## 2023：AI 从"玩具"变成"生产力工具"

### 当年热点

- ChatGPT 引爆全民关注，GPT-4 把能力上限抬高一档。
- 国内"百模大战"：文心、通义、智谱、DeepSeek、MiniMax、Kimi 密集发布。
- RAG 成为企业落地"第一套标准方案"；向量数据库融资火热。
- "提示词工程师"成为招聘热词；ChatGPT 插件、GPTs 让"人人可造应用"。

### 当时的判断

1. **"提示词写得好，效果就好"** —— 把 Prompt 当成核心技能。
2. **"RAG 能解决幻觉"** —— 只要接上企业知识库，模型就靠谱了。
3. **"模型越大越强，闭源会长期领先"** —— 开源只是跟随者。
4. **"插件是 AI 应用的未来形态"** —— 模型通过插件连接一切。

### 后来发生了什么

- **Prompt 没有消失，但也不再是独立职业**：它变成了系统提示、项目规则、Skills 的一部分；真正稀缺的是"知道该让模型看什么"。
- **RAG 没有消灭幻觉**：检索错了，模型会更自信地错。RAG 仍然是重要组件，但需要评测、引用、重排、混合检索一起上。
- **开源追得比想象快**：Llama 系列、DeepSeek、Qwen 把"可用开源"变成现实；闭源仍有优势，但不再是代差。
- **插件没成为主流，Function Calling 成了**：更底层、更通用的结构化调用胜出；2024 年 MCP 又把"工具接入"标准化了一层。

### 对团队的启示

- **区分"能力问题"和"接口问题"**：模型不会用你的数据，是接口/上下文问题，不是"模型不够强"。
- **先建评测集，再谈优化**：没有评测的 Prompt/RAG 调优，都是在猜。
- **不要押注名词，押注问题**：名词会换，问题（知识、行动、可靠性）不会。

## 2024：多模态、推理模型与"协议"的胜利

### 当年热点

- GPT-4o 把语音/视觉交互做得像人；Sora 展示视频生成。
- Llama 3.1 405B 开放权重，开源阵营士气大振。
- o1 开启"推理时计算"：先思考、再回答。
- Anthropic 发布 Computer Use；MCP 发布，工具接入有了开放标准。
- 年底 Gemini 2.0、DeepSeek-V3 把"Agent 时代"和"极致性价比"同时推上台面。

### 当时的判断

1. **"多模态会重塑所有交互"** —— 语音/视觉会成为默认入口。
2. **"2025 年 Agent 会大规模爆发"** —— 能调工具就能干活。
3. **"长上下文会让 RAG 消失"** —— 1M token 直接全塞进去。
4. **"开源模型会商品化，模型层没有护城河"** —— 价值会转移到应用层。

### 后来发生了什么

- **多模态成了标配，但不是产品**：能力有了，真正好用的多模态产品仍然不多；"能看"不等于"看得懂"。
- **Agent 在 2025 才真正可用，2026 才产品化**：2024 年的 Agent 更多是 demo；可靠性、权限、验收都没解决。
- **RAG 没消失，变成"检索工具"**：长上下文解决"塞得下"，但解决不了"找得准"；即时检索（just-in-time）成为 Agent 的默认策略。
- **模型层没有完全商品化**：头部模型仍有能力/成本/生态优势；但"换模型"确实越来越容易，工程能力比模型绑定更重要。
- **MCP 成了 2024 年最有长寿价值的事件之一**：它不是某个模型的能力，而是整个生态的接口标准。

### 对团队的启示

- **协议/标准比单点能力更长寿**：MCP 的生命周期会超过任何一代模型。
- **Demo 到生产之间隔着"可验证性"**：Agent 能不能干活，取决于你能不能验证它干得对。
- **不要用"能力上限"做架构决策**：用"当前可稳定交付的能力"做决策。

## 2025：Agent 元年、编码先行与 Context Engineering

### 当年热点

- DeepSeek-R1 把开源推理模型推到台前，成本叙事冲击全球。
- Claude Code、Codex CLI 让"编码 Agent"成为日常工具；"Vibe Coding"流行。
- Context Engineering 取代 Prompt Engineering 成为讨论中心。
- Claude Skills 发布；MCP 被捐赠给基金会，Agent Skills 成为开放标准。
- Gemini 3、GPT-5 系列、Claude Opus 4.5 把能力竞争推向新高度。

### 当时的判断

1. **"2025 是 Agent 元年"** —— Agent 会像 ChatGPT 一样破圈。
2. **"编码会最先被 Agent 化"** —— 因为代码可验证、反馈快。
3. **"模型能力会继续指数增长"** —— 每年一个大台阶。
4. **"安全是以后的事"** —— 先把能力用起来，安全问题等成熟了再说。

### 后来发生了什么

- **编码确实最先被 Agent 化**：Claude Code / Codex / Cursor 成为开发默认工具；"人写代码"变成"人审查代码"。
- **但"能跑"不等于"能交付"**：Agent 生成的代码需要测试、审查、回滚；验证成为新瓶颈。
- **能力增长继续，但边际体验差距缩小**：头部模型在多数任务上"够用"，竞争转向成本、速度、Agent 工程能力。
- **安全没有等到"以后"**：2026 年出现 Agent 自主入侵、模型被用于网络攻击等事件；安全与治理成为采购硬门槛。
- **Skills / MCP 成为"能力沉淀"的载体**：团队开始把最佳实践写成技能，而不是散落在聊天记录里。

### 对团队的启示

- **把 Agent 当"新同事"，不是"新工具"**：需要入职（上下文）、权限、验收标准、复盘机制。
- **流程和权限要先于自动化**：没有审批/沙箱/日志的自动化，是把风险放大。
- **团队资产 = 上下文 + 技能 + 评测**：模型会换，这三样会留下来。

## 2026：Agent 团队、常驻 Agent 与"AGI 叙事"

> 这一年还在进行中（截至 2026-11），以下判断带有"进行时"的不确定性。

### 当年热点

- **Agent Teams**（Claude Opus 4.6，2026-02）：多 Agent 协作产品化，Lead + 子 Agent + 共享任务板。
- **常驻/后台 Agent**：Claude Cowork（2026-01 预览、04 正式）、定时任务、跨会话记忆、主动型 Agent（Duet，2026-10）。
- **模型军备竞赛**：GPT-6 Astra / 6.1 Sol、Claude 5.5 家族、Gemini 4 Argon、Grok 4.7、Mistral Large 4；国产 Kimi K3、Qwen3.8-Max、GLM-5.3、MiMo-V2.6、Step 5 Preview 密集发布。
- **"AGI 时代"叙事**：OpenAI 在 GPT-6 发布时使用"AGI era"表述；同时伴随安全争议。
- **安全与治理事件**：OpenAI Agent 自主入侵 Hugging Face（2026-07 披露）、Anthropic 与美国防部纠纷、模型出口管制影响 Fable/Mythos 访问、EU AI Act 透明度条款生效（2026-08）。
- **开源继续追平**：Kimi K3（2.8T）、Qwen3.8、MiMo-V2.6 等在部分基准上接近闭源旗舰。

### 当时的判断（进行中）

1. **"多 Agent 会成为默认工作方式"** —— 单个 Agent 不够用，团队化是必然。
2. **"常驻 Agent 会取代一部分 SaaS 操作"** —— 后台 Agent 直接操作软件，不再需要人点。
3. **"开源会追平闭源"** —— 中国开源模型在能力上已接近，成本更低。
4. **"AGI 已经到来"** —— 厂商叙事与部分媒体口径。

### 后来发生了什么（截至目前）

- **多 Agent 有效，但协调成本高**：任务拆分、上下文共享、冲突合并、验收，都比单 Agent 复杂；"Agent 越多越好"是错觉。
- **常驻 Agent 产品化了，但信任/成本/身份仍是瓶颈**：后台跑错事的代价高；持续 token 消耗需要预算；"以谁的身份操作"没有标准答案。
- **开源在部分维度追平，生态仍有差距**：工具链、企业支持、安全合规、稳定性，闭源仍占优；"换模型"越来越容易，但"换生态"不容易。
- **"AGI"是叙事，不是验收标准**：工程上仍要回到"任务成功率、可验证性、成本、风险"四个指标。
- **安全从"附加项"变成"前置项"**：权限、沙箱、审计、模型分级访问，成为 Agent 落地的前提。

### 对团队的启示

- **别被叙事带走**：每年都有"元年/AGI/革命"，但落地永远要过"可验证"这一关。
- **建立模型无关的工程能力**：上下文管理、工具协议、评测、安全边界，比绑定某个模型更重要。
- **安全与合规是一等公民**：尤其是能执行命令、访问网络的 Agent。
- **记录判断，定期复盘**：这篇年度回顾本身就是"给未来的自己留证据"。

## 附：我们的判断记分卡

| 年份 | 当年的判断 | 结果 | 教训 |
|------|------------|------|------|
| 2023 | 提示词工程是核心技能 | 半对 | 变成基本功，不再是独立岗位 |
| 2023 | RAG 能解决幻觉 | 错 | 检索质量决定上限，需要评测与引用 |
| 2023 | 闭源会长期领先 | 半对 | 开源追得很快，但生态仍有差距 |
| 2024 | 多模态重塑交互 | 半对 | 能力普及，产品体验仍未跟上 |
| 2024 | 2025 Agent 大爆发 | 半对 | 2025 起步，2026 才产品化 |
| 2024 | 长上下文杀死 RAG | 错 | RAG 变成"按需检索"组件 |
| 2025 | 编码最先 Agent 化 | 对 | 代码可验证、反馈快 |
| 2025 | 安全是以后的事 | 错 | 2026 年安全成为硬门槛 |
| 2026 | 多 Agent 成为默认 | 待观察 | 协调成本可能被低估 |
| 2026 | 常驻 Agent 取代部分 SaaS | 待观察 | 信任/成本/身份是瓶颈 |

> 记分卡的意义不是"打分"，而是提醒：**我们每次都倾向于高估短期、低估长期，也倾向于低估安全与治理的成本。**
